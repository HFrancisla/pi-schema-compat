# pi-schema-compat

[English](README.md) | [简体中文](README.zh-CN.md)

A tiny [Pi](https://github.com/earendil-works/pi) extension that fixes `Invalid schema for function '...': null is not of type "array"` errors from strict OpenAI-compatible gateways.

## Why

JSON Schema allows an object schema with no `required` field. Pi and its extensions correctly create these schemas for tools with entirely optional parameters. Some OpenAI-compatible gateways incorrectly require `required` to be an array even for objects without mandatory properties.

This issue can affect built-in `ls` as well as tools from `pi-subagents`, `pi-web-access`, `pi-lens`, and other extensions. It may fail **before** the model calls any tool.

## Install

Requires **Pi 1.2.0 or newer**. Once the package is published to npm:

```bash
pi install npm:@hfrancisla/pi-schema-compat
```

Restart Pi or run `/reload`. The extension applies automatically to Chat Completions-shaped requests.

For local testing without installing:

```bash
pi --extension ./index.js --no-extensions --tools ls -p "Hello"
```

`--no-extensions` disables automatic discovery but explicitly passed `--extension` is still loaded.

## How it works

The native `before_provider_request` event runs after Pi prepares the provider payload and before sending HTTP. This extension recursively adds `"required": []` **only** to JSON Schema object nodes that lack a valid `required` array, at `tools[].function.parameters`.

For example, a tool definition generated by Pi may look like:

```json
{"type":"object","properties":{"path":{"type":"string"}}}
```

The outgoing provider request uses:

```json
{"type":"object","properties":{"path":{"type":"string"}},"required":[]}
```

Existing arrays (such as `"required": ["path"]`) are preserved. Nested objects in `properties`, `items`, `anyOf` / `oneOf` / `allOf`, `$defs`, and other standard JSON Schema positions are handled too. The extension is immutable and idempotent, and does **not** re-register, replace, or disable tools.

## Diagnostics

Use `/schema-compat` in Pi to display the number of provider requests, tools, and schema objects normalized in the current process. No prompts, credentials, or raw request data are saved or logged.

## Development

```bash
npm run verify
npm pack --dry-run
```

There is no build step and no runtime dependency. The published extension is plain ESM JavaScript.

## Release

```bash
npm run verify
npm pack --dry-run
npm publish --access public
```

Publishing requires your own npm registry authentication and an account authorized to publish under `@hfrancisla`.

## Scope and limitations

This resolves **missing `required` arrays**, not all upstream incompatibilities. Some gateways reject additional JSON Schema keywords or have intermittent service-side routing issues. The patch intentionally avoids unrelated provider request formats and does not change existing valid required arrays. It does not enable OpenAI strict mode or rewrite all optional fields as required.
